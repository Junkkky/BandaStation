modular_bandastation/bug_reports/README.md

Порт Paradise #30376, изначально из CM-SS13. Форма на русском использует штатные компоненты TGUI.

report-issue во вкладке OOC, кнопка в лобби и ESC → Report Bug открывают форму. Игрок заполняет заголовок, ожидаемое и фактическое поведение, последствия, шаги воспроизведения и необязательные логи. Отправка на проверку доступна раз в пять минут на ckey. Администраторы с любым из прав R_ADMIN, R_DEBUG рассматривают отчёты через View Bug Reports в Debug. Закрытие окна проверки оставляет отчёт в очереди и освобождает его для коллег. Потеря прав проверяющего также закрывает окно и освобождает отчёт. Подтверждение создаёт GitHub issue; отклонение уведомляет автора.

В приватной серверной конфигурации (config/dev_overrides.txt для локалки):

GITHUBURL https://github.com/SpaceStation220/Primera
GITHUB_API_TOKEN <токен выбранного репозитория>

Для fine-grained токена достаточно доступа к выбранному репозиторию и Issues: Read and write. Токен скрыт и заблокирован для административных изменений через VV/proc call, не передаётся в TGUI и не хранится в репозитории. Команда всегда открывает новую форму в игре. Без токена публикация недоступна, отчёты остаются в очереди до настройки; переход к старой форме GitHub удалён.

При ошибке API отчёт остаётся в очереди. После сетевого сбоя перед повторным подтверждением проверьте Issues: запрос мог дойти до GitHub без ответа серверу. Очередь и cooldown живут до перезапуска сервера, как в исходном PR.

Для ручной проверки: отправить заполненную форму, убедиться в cooldown; открыть её через View Bug Reports, закрыть и открыть другим сотрудником; повторить с потерей прав проверяющего и убедиться, что отчёт освобождается; проверить отклонение и уведомление автора. На тестовом репозитории подтвердить отчёт, проверить поля, раунд, версии BYOND, коммиты и test merges в issue; повторить с неверным токеном и убедиться, что отчёт остаётся в очереди.

Unit tests bug_report_validation, bug_report_repository, bug_report_cooldown, bug_report_lifecycle, bug_report_deadmin не отправляют HTTP-запросов. Последний моделирует потерю прав без подключённого клиента, проверяя настоящее закрытие TGUI, освобождение отчёта и очистку реестров.
